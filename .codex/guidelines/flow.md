# Как устроен цикл

Фреймворк решает одну проблему: **контекст модели — ненадёжное хранилище
обещаний**. Что решили на 20-м ходу, к 60-му размылось; что обещали в пункте 4,
к пункту 9 забылось; «сделано» без доказательства неотличимо от «сказано, что
сделано».

Поэтому обещания живут **вне контекста** — в файлах, у каждого шага есть
проверяемый критерий, а закрытие итерации подтверждает **свежий агент**,
который лога не видел.

## Файлы

```
flow/
  PROJECT.md            профиль: стек, команды, слои, зоны риска, инварианты, стайлгайды
  SPEC.md               спецификация проекта на языке продукта — пишет /interview
  DECISIONS.md          долговечные решения, переживают итерации — пополняет /ship
  ROADMAP.md            итерации целиком, с прогрессом — только для многоитерационной работы
  MANUAL.md             что владельцу сделать руками + ссылка на артефакт-инструкцию — /go, /ship
  design/README.md      откуда берётся дизайн, токены, экраны — пишет /mockups
  quick.md              строка на каждый /go без плана: дата · что · коммит
  NN-slug/              текущая итерация
    spec.md             спека крупной фичи (если делали /interview для неё)
    plan.md             ЕДИНСТВЕННЫЙ источник правды о том, что делаем и что готово
    tests.md            спека тестов: сценарий → тест → шаг → статус
    api.md              контракт эндпоинтов — если итерация их добавляет или меняет
    notes.md            решения, сюрпризы, грабли — пишет только /save
    log/NN-шаг.md       что сделано на шаге + доказательства
  done/                 закрытые итерации
```

`flow/` коммитится вместе с кодом: план — часть работы, а не черновик.
Исключение — если корень проекта не репозиторий (несколько репо внутри);
тогда `flow/` лежит в корне и не версионируется, и это указано в `PROJECT.md`.

## Три размера работы

Церемония должна быть пропорциональна задаче. Иначе её перестанут соблюдать —
целиком, а не только в лишней части.

| Размер | Что это | Как работаем |
|---|---|---|
| **Мелкая** | правка в 1–2 файлах, понятно с ходу | `/go «текст задачи»` — без плана. Гейты по риск-роутеру работают, след остаётся в `quick.md` |
| **Фича** | 3–10 шагов, один связный кусок | `/plan` → одна итерация → `/go` × N → `/check` → `/ship` |
| **Крупная фича** | не хватит одного плана; нужны решения о поведении | `/interview` (фича) → `/plan` → … |
| **Проект с нуля** | пустой репозиторий | `/interview` (проект) → `/mockups` если есть экраны → `/plan` → `ROADMAP.md` + детально **только первая** итерация |

**Прогрессивная детализация — правило, а не оптимизация.** План на пятую
итерацию, написанный сегодня, будет неверен к моменту, когда до неё дойдут.
Планируем детально ровно один шаг вперёд.

## Формат шага

Шаг — это две строки: **что** и **как проверить**.

```markdown
- [ ] 3. Хранилище секретов: envelope-шифрование
      Готово: T4, T5 зелёные; в дампе БД нет plaintext-значений
```

«Готово» — это команда, наблюдение или ссылка на тест из `tests.md`. Не
«работает корректно», не «покрыто тестами». Критерий, который нельзя
выполнить и посмотреть, — не критерий, и шаг с ним закрыть нельзя.
`flow-lint` такие критерии не пропустит.

**Параллельные шаги** помечаются `∥` перед номером:

```markdown
- [ ] ∥ 2. CI: линтер, типы, тесты, цикл миграций
      Готово: CI зелёный на ветке; сломанный тест роняет пайплайн
- [ ] ∥ 3. Схема ядра: пользователи, роли, проекты, окружения. Миграция
      Готово: alembic check чист; цикл вперёд-назад-вперёд проходит
```

Соседние `∥`-шаги образуют группу: они не зависят друг от друга и не
пересекаются по файлам. `/go` вправе отдать всю группу нескольким `builder`
одним сообщением. Порядок закрытия внутри группы не важен, и `flow-lint` не
считает `[ ] ∥` выше `[~]` проскоченным шагом.

**Стоп-точка владельца** — маркер `⏸` перед номером: шаг, который нельзя
закрыть без решения владельца в чате (ревью макетов, выбор варианта, приёмка
демо). Критерий такого шага — «владелец утвердил …», и `/go` не ставит `[x]`,
пока утверждения нет в разговоре.

```markdown
- [ ] ⏸4. Ревью макетов владельцем: выбор варианта и правки
      Готово: владелец утвердил вариант в чате; выбранные артборды и дата — в `design/README.md`
```

## Заходы

Заход — несколько шагов подряд, которые `/go` выполняет **одним запуском**:
`/go 1-4`. Каждый шаг внутри захода проходит полный цикл — критерий, гейты,
`log/`, коммит, — но между шагами `/go` не останавливается на отчёт.

План предлагает заходы разделом в конце списка шагов:

```markdown
## Заходы

- 1–3 · подготовка без владельца: выкат, граница транзакции, варианты макетов
- 4 · ⏸ ревью макетов
- 5–7 · серверная часть входа и сессий — одна зона, один набор гейтов
```

Как резать:
- **Заход кончается там, где владельцу есть что посмотреть или решить**:
  макеты, контракт, спорное решение, демо. Шаг `⏸` всегда последний в заходе.
- В заходе — шаги, которые **строятся друг на друге без развилок**: если
  после шага может понадобиться «а давай иначе», дальше идти нельзя.
- Не больше 4 шагов: длинный заход копит непроверенные допущения, ради
  борьбы с которыми и существует остановка.

Заход — предложение, а не обязательство: `/go` без диапазона по-прежнему
делает один шаг, а владелец вправе передать любой диапазон.

## Статусы

| | Значение |
|---|---|
| `[ ]` | не начат |
| `[~]` | текущий (ровно один на весь план; в `∥`-группе — по одному на каждого исполнителя) |
| `[x]` | сделан, критерий выполнен, доказательство в `log/` |
| `[S]` | пропущен — **в той же строке причина** после ` — ` |
| `[!]` | заблокирован — **в той же строке чем** после ` — ` |

`[x]` без записи в `log/` — нарушение. `flow-lint` и `/check` такие шаги найдут.

## Что где живёт

| Что | Куда | Кто пишет |
|---|---|---|
| Что строим и для кого | `SPEC.md` / `NN/spec.md` | `/interview` |
| Состояние: какой шаг следующий | `plan.md` | `/plan`, `/go` |
| Какие тесты обещаны и какие есть | `tests.md` | `/plan`, `/go` |
| Контракт между фронтом и бэком | `api.md` | шаг «контракт API» |
| Доказательства: вывод тестов, что изменено | `log/NN-шаг.md` | `/go` |
| Почему: решения, сюрпризы, грабли этой итерации | `notes.md` | только `/save` |
| Решения, которые переживут итерацию | `DECISIONS.md` | `/ship` (переносит из `notes.md`), `/interview` |
| Стек, команды, зоны риска, инварианты | `PROJECT.md` | `/plan` при первом запуске, `/ship` (инварианты) |
| Что сделать руками: секреты, регистрации, доступы, решения | `MANUAL.md` + артефакт | `/go` (пункты шага), `/ship` (сверка) |
| Дизайн: путь, токены, экраны | `design/README.md` | `/mockups` |
| Мелкие правки без плана | `quick.md` | `/go` |

`plan.md` — план, а не журнал. Отчёты, вывод тестов и вердикты ревью в него
не пишутся: он должен читаться за 20 секунд через неделю после перерыва.

## Команды

```
/interview  понять задачу: спека на языке продукта — проект или крупная фича
/mockups    откуда берётся дизайн: свой / сгенерировать / без макетов
/plan       разложить на итерации и шаги с критериями; спека тестов; профиль проекта
/go         выполнить ОДИН шаг (или ∥-группу), /go N-M — заход: сделать → доказать → гейты → коммит → стоп
/verify     доказать: механика за ноль токенов, ревьюер — только если она нашла повод
/check      свежим взглядом проверить, что заявленное реально сделано и тесты настоящие
/ship       закрыть итерацию: полные проверки, premortem, демо, решения, ветки, PR-лист
/rca        найти причину бага по доказательствам, а не по правдоподобию
/save       записать решения и грабли перед /clear
```

## Правило одного шага

`/go` выполняет **ровно один** шаг (или одну `∥`-группу) и останавливается.
Не «заодно ещё два». Больше — только диапазоном, который назвал владелец
(`/go 1-4`), и тогда остановка переезжает в конец захода, а не исчезает:
первое же отклонение — красный критерий, blocker гейта, решение, которого нет
в плане, ручное действие, без которого следующий шаг не имеет смысла, — и
заход обрывается на этом шаге с отчётом.

Это стоит лишних ходов и выглядит медленнее — а покупает то, ради чего всё
затевалось: после каждого шага есть точка, где видно результат и можно
свернуть. Агент, прошедший восемь шагов подряд, к восьмому уже строит на своих
же непроверенных допущениях, и разбирать это дороже, чем восемь остановок.

В заходе остановка переезжает в конец, но проверки — нет. Дешёвое остаётся на
каждом шаге: механика `/verify`, линтер, типы, точечные тесты, `log/` и
коммит — они не стоят токенов и дают откат по шагам. В конец переезжает только
дорогое: `reviewer`, `premortem` и прочие гейты уровня 1, один раз по
совокупному дифу. Исключение — шаг, задевший зону риска из `PROJECT.md`: он
гейтится сразу, не дожидаясь конца захода.

Единственное исключение — шаг оказался тривиальнее, чем думали, и следующий
физически не имеет смысла отдельно. Тогда объединить и **сказать об этом в
отчёте**.

## Механическое принуждение

Три части фреймворка — не промпт, и потому работают независимо от того, что
агент решил в этот раз.

**`.codex/hooks/flow-lint.py`** проверяет планы при каждом `git commit` (хук
`PreToolUse`) и блокирует коммит, если: больше одного `[~]`; есть `[ ]` выше
текущего; у шага нет «Готово:» или оно невыполнимое; `[x]` без файла в `log/`;
`[S]`/`[!]` без причины; заходы ссылаются на несуществующие шаги, пересекаются
или идут не по порядку; шаг `⏸` стоит не последним в своём заходе. Отдельно —
если диф задел **зону риска** из `PROJECT.md`, а в свежем файле `log/` нет
строки `Гейты: зона «…» — …`: гейт, о котором нет отметки, считается
непройденным. Строгость адресная: блокирует план, по которому идёт работа, а
про заброшенный план прошлой итерации только напоминает. При старте сессии
печатает текущий шаг; перед сжатием контекста напоминает про `/save`.
Запустить руками: `python .codex/hooks/flow-lint.py`.

**`.codex/hooks/big-file-guard.py`** не даёт открыть файл тяжелее 200 КБ —
ни `Read`, ни `cat`. Такие файлы почти всегда производные: сборка, экспорт,
бандл, дамп. Нужный кусок достаётся `grep` и `sed -n 'A,Bp'`. Порог меняется
переменной `FLOW_MAX_READ_BYTES`.

**`.codex/tools/verify.py`** — не хук, а инструмент `/verify`: разбирает диф
и находит то, за чем иначе идут к ревьюеру. Файлы, где изменились только
пробелы и переносы строк (`--fix` их откатывает); секреты и файлы окружения;
отладочный мусор и `TODO`; проглоченные ошибки; тронутые зависимости и
миграции; крупные дифы; задетые зоны риска. Стоит ноль токенов, поэтому идёт
первым — ревьюер включается, только если эта проверка нашла повод.
