# Решения

Долговечные решения проекта — те, что переживают итерацию и должны быть
известны любому, кто откроет проект через месяц. Не журнал работы: одна
запись — одно решение, с причиной.

Пополняется `/ship` (переносит из `notes.md` итерации) и `/interview`
(решения, принятые на интервью). Читается `/plan`, `/interview`, `builder`.

Формат:

```markdown
## D1 · Гранты ссылаются на id окружения, не на имя

**Решение.** Грант хранит идентификатор окружения. Имя — только для отображения.
**Почему.** Переименование окружения давало доступ к чужим секретам, если имя
совпадало с именем из гранта.
**Дата.** 2026-09-09 · итерация 1
```

Отменённое решение не удаляется — помечается `~~D1~~` со ссылкой на новое:
история того, почему передумали, ценнее чистоты списка.

---

## D1 · Реальные секреты живут вне Git worktree

**Решение.** `.deploy/` содержит только commit-safe YAML, examples и стабильный
project-id. Реальные secret files и SSH key pair размещаются в project-scoped
OS-local store; CI задаёт внешний root через `ANSIBLE_DEPLOY_SECRETS_DIR`.
**Почему.** `.gitignore` не защищает от `git add -f`, IDE/cloud sync и архивов,
а абсолютные machine paths делают config непереносимым.
**Дата.** 2026-10-04 · итерация 1

## D2 · Restore drill отделён от Production

**Решение.** Backup source environment и restore target — разные параметры;
приёмка восстанавливает Production backup на отдельный Restore Drill VPS.
**Почему.** Проверка восстановления непосредственно на Production разрушительна
и противоречит критерию безопасной финальной приёмки.
**Дата.** 2026-10-04 · roadmap
