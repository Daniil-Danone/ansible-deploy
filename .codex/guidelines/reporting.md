# Отчёт владельцу: ручные действия и выделение важного

Владелец читает отчёт бегло, часто с телефона, и через день не вспомнит, что
было в середине третьего абзаца. Ручное действие, спрятанное в тексте, не будет
сделано — а забытая переменная окружения ломает выкат надёжнее любого бага.
Поэтому важное выделяется так, чтобы его нельзя было пропустить при беглом
просмотре.

## Ручные действия

**Ручное действие** — всё, что агент не может или не имеет права сделать сам:
регистрация в сторонних сервисах (BotFather, OAuth-консоли, домены), боевые
секреты и значения окружения, настройки репозитория и тарифа, доступы по SSH,
применение миграций на базе, которую нельзя выбросить, покупки, решения,
которые принадлежат владельцу.

Появилось ручное действие — делается три вещи.

### 1. Блок в чате — отдельно, а не в тексте

Сразу после первой строки отчёта, до технических подробностей:

```
> 🛠️ **Нужно сделать руками** — 2 пункта · инструкция: <ссылка на артефакт>
> 1. **Зарегистрировать OIDC-клиента в BotFather** — без этого вход не работает · сейчас
> 2. **Решить, переходить ли на GitHub Team** — без него обязательные проверки не включить · до шага 10
```

У каждого пункта:
- **действие жирным**, глаголом: «зарегистрировать», «задать», «решить»;
- **зачем** — что сломается или останется незащищённым без него;
- **когда** — «сейчас», «до шага N», «до выката», «до итерации N».

Пунктов нет — блок не пишется. Пустое «ручных действий нет» — шум.

### 2. Артефакт-инструкция

Опубликовать страницу (инструмент Artifact) с пошаговой инструкцией:
- по каждому пункту — **где** (сервис, раздел, кнопка), **что** ввести,
  **какой командой проверить** и **что должно получиться**;
- команды — отдельными копируемыми блоками;
- чек-лист, где отметки сохраняются (возможность `artifact` — страница
  публикует свою новую версию), чтобы владелец мог вести его с любого
  устройства, а агент — прочитать, что уже сделано;
- невыполнимое сейчас (нужен тариф, доступ, решение) — отдельным блоком с
  вариантами, а не пунктом чек-листа.

**Один артефакт на проект.** Новые пункты — правка той же страницы по тому же
адресу, а не новая страница на каждый шаг: иначе через неделю их пять, и
актуальная неизвестна. Перед правкой — прочитать текущую версию
(`action: "read"`), чтобы не затереть отметки владельца.

**Секретов в артефакте нет** — только имена переменных и то, как значение
сгенерировать (`openssl rand -base64 32`).

### 3. Реестр `flow/MANUAL.md`

Переживает `/clear` и новую сессию: ссылка на артефакт и таблица пунктов —
что, откуда (шаг), когда нужно, статус. `/go` дописывает пункты своего шага,
`/ship` сверяет: открытые пункты попадают в отчёт закрытия итерации.

### Не выдумывать чужие интерфейсы

Названия меню, кнопок и команд в сторонних сервисах берутся только из
документации, из кода или конфигов проекта, или из проверенного соседнего
проекта. Источника нет — так и написать: «названия пунктов могут отличаться,
ищи раздел про …». Выдуманная команда хуже, чем честное «не знаю где».

**Невыполнимое сказать прямо.** Упёрлись в тариф, права, отсутствующий доступ —
что именно мешает, чем подтверждено (ответ API, сообщение об ошибке) и
какие есть варианты. Не выдавать это за обычный пункт «включи галочку».

## Отчёт шага и захода

```
Шаг 3/8: Хранилище секретов — готово

> 🛠️ **Нужно сделать руками** — 1 пункт · инструкция: <ссылка на артефакт>
> 1. **Задать `KEK_PATH` на сервере** — без него api не стартует в prod · до шага 5

Критерий: T4, T5 зелёные ✓ · в дампе plaintext не найден ✓
Тесты: T4 tests/test_crypto.py::test_roundtrip · T5 ::test_tamper_fails
Заглушка: T5 красный на «шифрование → тождество» ✓, возвращено, зелёный ✓
Проверки: ruff чисто · mypy чисто · 118 passed
Гейты: reviewer PASS · premortem пропущен (зона не задета)
Коммит: a3f21c9 feat: envelope-шифрование секретов [backend]

Следующий: 4. Ротация мастер-ключа

Что это меняет: значения секретов больше не лежат в базе в открытом виде —
компрометация дампа не отдаёт креды.
```

Последние две строки обязательны: терминал прокручивается, а вернуться через
день нужно без перечитывания лога. «Следующий» — с заходом из плана, если он
есть: `Следующий: заход 5–7 (/go 5-7) — сессии и аудит входа`.

**Отчёт захода** — тот же формат, но блок «Критерий … Коммит» — по строке на
шаг, и первой строкой — где заход кончился и почему:

```
Заход 1–4: закрыты 1, 2, 3 · стоп на ⏸4 — жду выбор варианта макета

1. Выкат — T1–T3 ✓ · учения в log/01 · reviewer PASS · 5e1c0a2 [backend]
2. Граница транзакции — T4 красный→зелёный ✓ · 212 passed · 9b7d1f4 [backend]
3. Варианты макетов — 3 варианта + 5 референсов · канвас: <ссылка>
4. ⏸ Выбери: A (плотная таблица) / B (карточки) / C (мастер-деталь) — что
   отличается и чем платим — в канвасе под каждым вариантом
```

Оборвался раньше конца — первой строкой шаг и причина обрыва, остальные шаги
диапазона не начаты.

Блок 🛠️ — только если ручные действия есть, и сразу под первой строкой, а не
в конце. Выделение важного и словарь эмодзи — ниже.

## Выделение в чате

**Итог — в первой строке.** Что получилось или не получилось, до подробностей.

**Эмодзи — словарь, а не украшение.** У каждого одно значение, других нет:

| | Значение |
|---|---|
| 🛠️ | нужно сделать руками |
| ⚠️ | важно: риск, неожиданность, то, что меняет планы |
| 🔴 🟡 🟢 | severity находки: blocker · major · minor |
| ✅ | сделано **и проверено** — рядом то, чем проверено |
| ❌ | не выполнено, красное, отказ |
| 🗃️ | миграция |
| 🔀 | PR и порядок мержа |
| 🔐 | секреты и доступы |
| ➡️ | следующий шаг |

Эмодзи без значения из таблицы не ставится — иначе они перестают что-либо
значить.

**Жирный** — то, что человек должен увидеть, пробегая глазами: итог, решение,
действие, число. Не больше одного-двух выделений на абзац: выделенное всё
равно что невыделенное.

**Цитата `>`** — для блока, который нельзя пропустить: ручные действия,
⚠️-предупреждение, решение, которое ждёт владельца.

**Таблица** — когда по строке на объект (шаги, пункты, джобы); **список** —
когда это действия; **абзац** — когда нужна причинная связь.

Тон — как у инженера, который пишет коллеге: коротко, по делу, без
восклицаний и без «отлично!».
